# WebP 图片及 v5 删除扩展

本版本保留完整 v4 读取能力和固定 v4 样例，不修改原有新增/更新语义。普通编辑仍写 v4；只有包含删除记录时写 v5。旧 v4 客户端明确拒绝 v5，不会静默丢弃删除指令。

## 删除记录

v5 在 `changes` 增加 `deleted?: {id,before:Lineup}[]`。ID 与快照 ID 必须一致，不能同时出现在新增/修改/删除中。删除记录不携带图片：只包含冲突检测所需快照，不要求提供 before 的图片文件。

- 浏览器依次处理包中的删除和新增/更新，删除不存在的 ID 为空操作。后面的包可以重新加入这个 ID，手动编辑始终最后应用。
- 仓库仅当现有点位匹配 before 时删除；已经不存在视为已应用，其他情况跳过并报告冲突。
- 持续编辑层：新建后删除抵消新增；修改后删除沿用首次 before；保存过的删除在后续编辑中保留。保存/导出仍只有一个累计包 ID。
- 历史记录增加可选 `deleted` 数量，旧记录缺失时按 0 显示。地图/点位数量包含删除涉及的点位，但不计入图片容量。

## 图片格式与旧包迁移

v4/v5 读取端仍验证 PNG/JPG/WebP 文件签名、大小和 SHA-256。校验通过后，PNG/JPG 在保存前转为 WebP；保存及导出只含 WebP，不持久保存原始图片字节。保留尺寸与透明通道，编码质量 86%；已有 WebP 不重复编码。大于 4800 万像素的输入拒绝解码，单张输入及压缩结果上限 12 MiB，包内图片总量上限 128 MiB，原有 ZIP/清单限制不变。

新浏览器上传使用随机 WebP 文件名。旧包图片转换后的文件名包含输出哈希片段，避免不同来源同名图片相撞。对应媒体条目增加可选 `original: {key,sha256}`，保留最早的逻辑图片路径及原始字节校验值；它不是原图内容，也不是用户身份凭据。该附加字段符合 v4 的可选元数据兼容规则。

仓库批量迁移记录在 `content/image-migrations.json`：旧路径 → `{key,sourceSha256,sha256}`。匹配旧 before/after 时，按图片最早身份比较，不因浏览器与仓库编码器生成不同 WebP 字节而制造冲突；名称、坐标、说明等真实变更仍参与比较。不同内容的新 WebP 使用不同路径，不覆盖旧路径文件。

构建产物包含 `mediaBytes`，让编辑页实时计算累计变更所涉及的全部图片大小。删除图片立即减少容量；上传完成使用压缩后的实际字节数更新容量。正在压缩时禁用编辑写入操作，防止异步压缩写到切换后的点位。

## 浏览器存储

保留原 `valo-lineup:v4:<部署路径>` localStorage 键和 IndexedDB 库名，不能因包格式增加而丢失旧资料。启动时读取旧清单、转换原图，全部图片写入成功后才提交新清单，再回收无引用旧图片；保留 packageId、revision 和图层顺序。迁移任务在同页面去重，并复用跨标签页锁/提交 token。迁移失败仍保留原清单与原图，以便重试或恢复。

迁移文件只描述图片替换，不计作玩家点位更新；此次 r6 包应用已在仓库历史中独立记录。

## 回归要求

`pnpm test` 保留 v4 固定样例、v5 删除/幂等/历史/回滚、旧图片快照匹配。`pnpm run test:browser` 验证 v4 PNG 包导入与原 IDB 图片启动迁移、Ctrl+V、压缩后用量、改名/阵营、新建阵营与区域、右侧拖动无选中、持续删除及刷新恢复，同时复测原有图片/地图缩放。
